# IBM Verify SDK for Android - Release 3.2.7

## Overview

Version 3.2.7 is a patch release that fixes a serialization crash in `TokenInfoSerializer` when `additionalData` contains `null` values or complex nested types, and updates the Jackson dependency suite to 2.22.1.

The key improvements center around:
- Correct serialization of `null` and nested values inside `TokenInfo.additionalData`
- Removal of the stale `jackson-bom` enforced platform block superseded by per-module force-resolution
- Jackson library update to 2.22.1

## Breaking Changes

None.

This is a backward-compatible patch release. All existing code using 3.2.6 will continue to work without modification.

## Bug Fixes

### 1. TokenInfoSerializer crash on null / complex additionalData values

**Fixed:** [`TokenInfoSerializer.serialize()`](../../sdk/authentication/src/main/java/com/ibm/security/verifysdk/authentication/model/TokenInfo.kt:303) no longer throws `JsonEncodingException` when `additionalData` contains `null` values or deeply nested maps and lists.

The previous serialization loop used a shallow `when` branch that stringified nested values with `vv.toString()`, turning `null` into the string `"null"` and failing to recurse into nested `Map` or `List` entries. This was the direct cause of the truncated crash `Failed to serialize MFA authenticator: r...` (`r...` being `kotlinx.serialization.json.internal.JsonEncodingException`).

The fix replaces the entire `when` block with a single call to the existing [`Any?.toJsonElement()`](../../sdk/core/src/main/java/com/ibm/security/verifysdk/core/extension/JsonExt.kt:23) extension from the Core SDK, which handles `null`, primitives, `JsonElement` passthrough, and nested maps/lists recursively.

## Improvements

### 1. Jackson dependency update to 2.22.1

**Updated:** All Jackson modules in [`build.gradle.kts`](../../build.gradle.kts) and [`gradle/libs.versions.toml`](../../gradle/libs.versions.toml)

The stale `enforcedPlatform("com.fasterxml.jackson:jackson-bom:2.15.3")` dependency block has also been removed from the root `build.gradle.kts`. It was superseded by the per-module force-resolution constraints introduced in 3.2.6 and was pinning Jackson to an older BOM version.

## Upgrade Notes

### Migration Notes

No code changes are required when upgrading from 3.2.6 to 3.2.7. The serialization fix is applied automatically — no changes to `TokenInfo` construction or persistence callbacks are needed.

## Known Issues

None identified for this release.

## Additional Notes

- This release is recommended for all applications that store MFA authenticators with `additionalData` fields that may contain `null` values or nested objects from OAuth/OIDC token responses
- The Jackson update brings the latest 2.22.x bug fixes and security patches
- The `jackson-bom` removal has no observable effect on behaviour; the per-module constraints already take precedence
