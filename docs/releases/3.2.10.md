# IBM Verify SDK for Android - Release 3.2.10

## Overview

Version 3.2.10 delivers four distinct improvements across the Authentication and Core SDKs:

1. **Ephemeral browser session** - `OAuthProvider` gains an `ephemeralSession` property that opens Chrome Custom Tabs in incognito mode, and the Authorization Code Flow demo adds a matching **Force login** toggle.
2. **`CancellationException` propagation hardening** - all network-facing methods in `OAuthProvider`, `CloudAuthenticatorService`, and `OnPremiseAuthenticatorService` now correctly re-throw `CancellationException` instead of swallowing it.
3. **`KeystoreHelper.createKeyPair` extended** - three new optional parameters give callers fine-grained control over authentication timeout, authenticator types, and device-lock requirements.
4. **Test hygiene** - all `@SuppressLint("DenyListedBlockingApi")` / `runBlocking` patterns replaced with `runTest`; request-body assertions strengthened; two previously `@Ignore`d tests re-enabled.

## Breaking Changes

None. This is a backward-compatible release. All existing code targeting 3.2.9 continues to compile and run without modification.

## New Features

### 1. Ephemeral browser session (`OAuthProvider.ephemeralSession`)

**Updated:** [`OAuthProvider`](../../sdk/authentication/src/main/java/com/ibm/security/verifysdk/authentication/api/OAuthProvider.kt), [`AuthenticationActivity`](../../sdk/authentication/src/main/java/com/ibm/security/verifysdk/authentication/AuthenticationActivity.kt)

New `ephemeralSession: Boolean` property (default `false`) on `OAuthProvider`. When `true`, `authorizeWithBrowser` passes the flag to `AuthenticationActivity` as an intent extra; `AuthenticationActivity` then calls `CustomTabsIntent.Builder.setEphemeralBrowsingEnabled(true)`, opening Chrome Custom Tabs in a private session where existing cookies, passwords, and history are not accessible and nothing written during the session persists.

This is the Android equivalent of the iOS `ASWebAuthenticationSession.prefersEphemeralWebBrowserSession` flag.

```kotlin
val provider = OAuthProvider(clientId = "your-client-id")
provider.ephemeralSession = true

provider.authorizeWithBrowser(
    url = URL("https://sdk.verify.ibm.com/oauth2/authorize"),
    redirectUrl = "verifydemo://callback",
    activity = this
)
```

**Requirements:** `androidx.browser` 1.8.0+ (1.10.0 is used in this release). Chrome 107+.

> **Note:** Ephemeral mode clears browser-side cookies only. To also force the authorization server to discard its session, combine with `prompt=login` in `additionalParameters` (see demo changes below).

`AuthenticationActivity` also received a full KDoc rewrite that documents the intent-extra contract (`url`, `ephemeralSession`) and the `RESULT_OK` / `RESULT_CANCELED` result codes. The previously reused `CustomTabsIntent.Builder` instance field was replaced with a per-call builder so `setEphemeralBrowsingEnabled` applies correctly each time.

### 2. `KeystoreHelper.createKeyPair` - three new optional parameters

**Updated:** [`KeystoreHelper`](../../sdk/core/src/main/java/com/ibm/security/verifysdk/core/helper/KeystoreHelper.kt)

| Parameter | Type | Default | Description |
|---|---|---|---|
| `userAuthenticationTimeout` | `Int` | `0` | Seconds the key remains authorised after authentication. `0` = per-use (re-auth on every operation). Applied on Android 11+ (API 30+) when `authenticationRequired = true`. |
| `userAuthenticationTypes` | `Int` | `AUTH_BIOMETRIC_STRONG \| AUTH_DEVICE_CREDENTIAL` | Bitmask forwarded to `setUserAuthenticationParameters`. Applied on Android 11+ (API 30+) when `authenticationRequired = true`. |
| `unlockedDeviceRequired` | `Boolean` | `false` | When `true`, calls `setUnlockedDeviceRequired(true)` - key usable only while device is unlocked. Requires API 28+; silently ignored on older versions. |

All three parameters are fully backward-compatible (all callers that previously omitted them continue to compile and behave identically).

On Android 10 and below the existing deprecated `setUserAuthenticationValidityDurationSeconds(-1)` fallback is preserved unchanged.

```kotlin
// Key valid for 30 s after auth, strong biometric only, must be unlocked
val publicKey = KeystoreHelper.createKeyPair(
    keyName = "mySigningKey",
    algorithm = "SHA256withRSA",
    purpose = KeyProperties.PURPOSE_SIGN,
    authenticationRequired = true,
    userAuthenticationTimeout = 30,
    userAuthenticationTypes = KeyProperties.AUTH_BIOMETRIC_STRONG,
    unlockedDeviceRequired = true
)
```

`encryptAndStorePrivateKey` and `decryptPrivateKey` received whitespace-only cleanup (trailing spaces removed). No functional change.

## Bug Fixes

### `CancellationException` propagation hardening

Every network-facing method that had a broad `catch (e: Throwable)` handler now has an explicit `catch (e: CancellationException) { throw e }` guard immediately before it. Without the guard, a coroutine scope cancellation mid-request is silently converted to `Result.failure(CancellationException)`, breaking Kotlin's structured concurrency.

**Affected methods and classes:**

| Class | Methods fixed |
|---|---|
| [`OAuthProvider`](../../sdk/authentication/src/main/java/com/ibm/security/verifysdk/authentication/api/OAuthProvider.kt) | `authorize` (code-flow overload), `authorize` (password-flow overload), `refresh` |
| [`CloudAuthenticatorService`](../../sdk/mfa/src/main/java/com/ibm/security/verifysdk/mfa/api/CloudAuthenticatorService.kt) | `nextTransaction`, `completeTransaction` |
| [`OnPremiseAuthenticatorService`](../../sdk/mfa/src/main/java/com/ibm/security/verifysdk/mfa/api/OnPremiseAuthenticatorService.kt) | `refreshToken`, `nextTransaction`, `remove` |

> **Note:** `CloudAuthenticatorService.refreshToken` and `login`, and `OnPremiseAuthenticatorService.completeTransaction` and `login` already carried the CE guard from earlier releases and were not changed.

**Consequences of the unfixed behaviour (for `refreshToken`):** The HTTP request may have already been delivered when the scope was cancelled. The server rotates the refresh token; if the response is not processed, the old (now consumed) refresh token remains in storage and the next refresh fails with HTTP 400.

## Demo Changes

### Authorization Code Flow demo - Force login toggle

**Updated:** [`examples/authcodeflow_demo`](../../examples/authcodeflow_demo/)

A **Force login** toggle has been added to the Settings card. When enabled, every authentication attempt opens Chrome Custom Tabs in incognito mode (`ephemeralSession = true`) and appends `prompt=login` to the authorization URI, guaranteeing a fresh login prompt regardless of browser or server session state.

| Session cache | Cleared by |
|---|---|
| Browser cookies / saved credentials | `ephemeralSession = true` |
| Authorization server session | `prompt=login` |

```kotlin
// MainActivity.kt - authenticateWithBrowser()
oAuthProvider = OAuthProvider(clientId = clientId)
oAuthProvider.ephemeralSession = useEphemeralSession
if (useEphemeralSession) {
    oAuthProvider.additionalParameters["prompt"] = "login"
}
```

## Upgrade Notes

No code changes are required when upgrading from 3.2.9 to 3.2.10.

To adopt `ephemeralSession`, set the property on your `OAuthProvider` instance before calling `authorizeWithBrowser`. To also force server re-authentication, add `"prompt" to "login"` in `additionalParameters`.

## Known Issues

`OnPremiseAuthenticatorService.nextTransaction` contains debug-level `log.error(…)` calls used during active development. These will be replaced with `log.debug(…)` in a subsequent patch.
