# IBM Verify SDK for Android - Release 3.2.14

## Overview

Version 3.2.14 is a patch release that resolves dependency scanning findings in the SDK's build tooling and updates Jackson. There are no changes to SDK source code or public APIs:

1. **Build classpath security updates** - Bouncy Castle, Jackson, FreeMarker, jsoup and Guava are pinned to patched versions on the Gradle buildscript classpath (Android Gradle Plugin lint / `sdk-common` and the Dokka plugin).
2. **Project configuration security updates** - Bouncy Castle is forced to `1.86` on all configurations, the forced Netty and Jackson versions are raised, and FreeMarker and jsoup are forced on Dokka configurations.
3. **Jackson 2.22.4 in the published `mfa` and `fido2` artifacts** - `jackson-core` and `jackson-dataformat-cbor`, the runtime dependencies of those modules, now declare `2.22.4`.

## Breaking Changes

None. This is a backward-compatible patch release. All existing code targeting 3.2.13 continues to compile and run without modification.

## Security

Dependency scanning (Mend) reported HIGH and CRITICAL findings against transitive dependencies of the build tooling. All of the libraries below are resolved transitively by the Android Gradle Plugin or the Dokka plugin.

| Library | Fixed version | Findings addressed |
|---|---|---|
| Bouncy Castle (`bcprov-jdk18on`, `bcpkix-jdk18on`, `bcutil-jdk18on`) | 1.86 | CVE-2025-14813, CVE-2026-5598, CVE-2026-71888, CVE-2026-71889 and others (Bouncy Castle < 1.86) |
| Jackson (`jackson-core`, `jackson-databind`) | 2.22.4 | CVE-2026-110879 (`jackson-databind`, CRITICAL), CVE-2026-89425 (`jackson-core`) |
| FreeMarker | 2.3.35 | CVE-2026-84939 |
| jsoup | 1.23.2 | CVE-2026-75140 |
| Guava | 33.7.2-jre | CVE-2026-102554 |

**Impact assessment:** Based on how the dependencies are wired, the SDK modules are not exposed through Bouncy Castle, FreeMarker, jsoup or Guava. The affected versions are only pulled in by build tooling, where they process the project's own sources and documentation. None of them appear in any SDK module's declared dependencies.

Jackson is the exception: `jackson-core` and `jackson-dataformat-cbor` are declared runtime dependencies of the `mfa` and `fido2` modules. The `jackson` version in [`gradle/libs.versions.toml`](../../gradle/libs.versions.toml) is raised from `2.22.3` to `2.22.4`, so the published artifacts now declare the patched version and SDK consumers receive the `jackson-core` fix (CVE-2026-89425). This is a patch bump within the same minor line, with no API changes expected.

### Where the pins are applied

All pins are in the root [`build.gradle.kts`](../../build.gradle.kts):

| Location | Scope | Change |
|---|---|---|
| `buildscript { dependencies { constraints { … } } }` | Gradle buildscript classpath (AGP, Dokka plugin) | Added Bouncy Castle 1.86, Jackson 2.22.4 (`annotations` stays on 2.22), FreeMarker 2.3.35, jsoup 1.23.2 and Guava 33.7.2-jre |
| `allprojects { configurations.configureEach { resolutionStrategy { force(…) } } }` | All project configurations | Added Bouncy Castle 1.86; raised the forced Jackson modules from 2.22.3 to 2.22.4 and Netty `codec-http2`, `codec-compression` and `handler-proxy` from 4.2.17.Final to 4.2.20.Final |
| Same block, restricted to configurations whose name contains `dokka` | Dokka generator classpaths | FreeMarker 2.3.35 and jsoup 1.23.2 |

The Jackson family is kept on a single version across `core`, `databind`, `dataformat-cbor`, `module-kotlin`, `dataformat-xml` and `module-jaxb-annotations`. `jackson-annotations` is versioned `2.22` and is intentionally not on `2.22.4`.

## Build System Changes

- `versionName` is `3.2.14` and `versionCode` is `132` in the root `build.gradle.kts` (previously `3.2.13` / `131`). Both are read by the `sdk.android.library` and `sdk.publish` convention plugins.
- The fallback version string used by the `sdk.android.library` and `sdk.publish` convention plugins in [`build-logic`](../../build-logic) when `versionName` is not set is updated to `3.2.14`. There are no other changes to the plugins, the Gradle wrapper (9.5.0), or the JDK 17 requirement.

## Test Coverage

No new or changed tests. No SDK source files changed.

Before tagging the release, confirm the following still pass with the new pins (the `mfa` and `fido2` tests exercise the Jackson CBOR dependency):

```bash
./gradlew testSdk
./gradlew assembleRelease
./gradlew dokkaGenerate
```

The Bouncy Castle and Jackson bumps affect the shared test classpaths, and the FreeMarker and jsoup pins affect only documentation generation.

## Upgrade Notes

No code changes are required when upgrading from 3.2.13 to 3.2.14.

Applications that depend on `mfa` or `fido2` will resolve Jackson `2.22.4` unless they pin another version. Applications that force an older Jackson version keep the older version and do not receive the `jackson-core` fix.

Forks that override the dependency pins in the root `build.gradle.kts` should merge the new `constraints` and `force(…)` entries listed under [Where the pins are applied](#where-the-pins-are-applied).
