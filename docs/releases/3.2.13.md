# IBM Verify SDK for Android - Release 3.2.13

## Overview

Version 3.2.13 is a patch release addressing TOTP/HOTP passcode generation stability, input normalization, and enrollment validation:

1. **Base32 secret normalization** — [`String.decodeBase32()`](../../sdk/core/src/main/java/com/ibm/security/verifysdk/core/extension/StringExt.kt) now normalizes Base32 secret input by stripping whitespace (`\s`), hyphens and dashes (`-`, `–`, `—`), and padding (`=`), while remaining case-insensitive.
2. **Empty secret validation at entry point** — [`OTPAuthenticator.fromQRScan`](../../sdk/mfa/src/main/java/com/ibm/security/verifysdk/mfa/OTPAuthenticator.kt) rejects empty and blank secret query parameters, preventing corrupt authenticator instances from being constructed during enrollment.
3. **Recoverable error handling in OTP generation** — [`OTPDescriptor.generatePasscode`](../../sdk/mfa/src/main/java/com/ibm/security/verifysdk/mfa/OTPDescriptor.kt) validates non-empty key material before constructing `SecretKeySpec` and catches decoding and cryptography errors, throwing structured [`MFAServiceException.General`](../../sdk/mfa/src/main/java/com/ibm/security/verifysdk/mfa/MFAServiceException.kt) instead of uncaught runtime exceptions (`IllegalArgumentException: Empty key` or invalid character crashes).
4. **Expanded test coverage** — JVM unit tests and on-device instrumented tests cover RFC 4648 Base32 test vectors, dashed, spaced, lowercase, unpadded, blank, empty, and invalid secret inputs.
5. **Build logic migration** — Shared Gradle configuration moved from `apply(from = …)` scripts to convention plugins in the new [`build-logic`](../../build-logic) included build (see [Build System Changes](#build-system-changes)).
6. **Logging cleanup** — Development-time trace output in [`OnPremiseAuthenticatorService`](../../sdk/mfa/src/main/java/com/ibm/security/verifysdk/mfa/api/OnPremiseAuthenticatorService.kt) was written with `log.error(…)`. It is now `log.debug(…)` (see [`OnPremiseAuthenticatorService` — log levels](#onpremiseauthenticatorservice--log-levels)).
7. **OW2 ASM security update to 9.11.1** — The ASM library family is pinned to `9.11.1` on all build, test and build-logic classpaths (see [Security: OW2 ASM 9.11.1](#security-ow2-asm-9111)).

## Breaking Changes

None. This is a backward-compatible patch release. All existing code targeting 3.2.12 continues to compile and run without modification.

## Bug Fixes

### `String.decodeBase32` — formatting character normalization

**Updated:** [`StringExt.kt`](../../sdk/core/src/main/java/com/ibm/security/verifysdk/core/extension/StringExt.kt)

Base32 secrets formatted with readability grouping hyphens/dashes (`ABCD-EFGH-...`), spaces or tabs, lowercase letters, or trailing padding characters previously caused `decodeBase32` to throw an uncaught `IllegalArgumentException: Invalid character in Base32 string: '-'`.

`String.decodeBase32()` now normalizes its input by filtering out all whitespace characters, hyphens/dashes (`-`, `–`, `—`), and padding (`=`), while converting ASCII characters to uppercase (`Locale.ROOT`).

### `OTPAuthenticator.fromQRScan` — non-blank secret validation

**Updated:** [`OTPAuthenticator.kt`](../../sdk/mfa/src/main/java/com/ibm/security/verifysdk/mfa/OTPAuthenticator.kt)

`OTPAuthenticator.fromQRScan` previously accepted URI parameters with empty `secret=` or whitespace-only values, creating authenticators with unworkable keys.

The parser now validates that the extracted secret is non-blank via `takeIf { it.isNotBlank() }`, returning `null` when given empty or whitespace-only secret URIs.

### `OTPDescriptor.generatePasscode` — recoverable error handling

**Updated:** [`OTPDescriptor.kt`](../../sdk/mfa/src/main/java/com/ibm/security/verifysdk/mfa/OTPDescriptor.kt)

When an account had an empty secret, a secret that decoded to zero bytes, or an invalid Base32 secret, `SecretKeySpec` construction threw a fatal `IllegalArgumentException: Empty key` or Base32 decoding failed with an unhandled exception, crashing host applications when generating or toggling passcodes.

`OTPDescriptor.generatePasscode(counter: Long)` now:
- Validates that decoded secret bytes are non-empty before passing them to `SecretKeySpec`.
- Catches decoding and cryptographic errors and throws [`MFAServiceException.General`](../../sdk/mfa/src/main/java/com/ibm/security/verifysdk/mfa/MFAServiceException.kt) (a structured `VerifySdkException`), allowing the host application to catch the failure and handle it gracefully (e.g. prompt for re-enrollment) without crashing.

### `OnPremiseAuthenticatorService` — log levels

**Updated:** [`OnPremiseAuthenticatorService.kt`](../../sdk/mfa/src/main/java/com/ibm/security/verifysdk/mfa/api/OnPremiseAuthenticatorService.kt)

`nextTransaction`, its helper `createPendingTransactions`, and the success message in `refreshToken` wrote routine trace output (call arguments, HTTP status, transaction and authenticator IDs, expiry checks) with `log.error(…)`. Every successful call therefore appeared as an error in host application logs and error-monitoring tools.

This trace output now uses `log.debug(…)`. Genuine failures (token persistence failure, non-success HTTP status, caught exceptions) remain at `log.error(…)`.

Two trace lines were removed rather than downgraded, because they wrote data that should not be logged at any level: the raw transaction response body and the pending transaction message text.

## Build System Changes

The shared Gradle scripts in the repository root were replaced by precompiled convention plugins in the new [`build-logic`](../../build-logic) included build (registered in [`settings.gradle.kts`](../../settings.gradle.kts) via `pluginManagement { includeBuild("build-logic") }`). This affects only the SDK's own build; published artifacts and coordinates are unchanged.

| Removed | Replaced by |
|---|---|
| `common-config.gradle` | `sdk.android.library` — namespace, SDK levels, build types, packaging, Java/Kotlin 17 toolchain, lint checks and common test dependencies |
| `common-config-ktor.gradle` | `sdk.ktor.client` — Ktor client dependencies |
| `common-config-demos.gradle` | `sdk.android.demo` — demo application defaults (this is also where the demo app version now lives) |
| `common-publish.gradle` | `sdk.publish` — `maven-publish`, sources/javadoc JARs and POM metadata |

Module build files now apply these plugins by id, for example:

```kotlin
plugins {
    id("sdk.android.library")
    id("sdk.ktor.client")
    id("sdk.publish")
}
```

Related build changes:

- `build-logic` takes the AGP, Kotlin and Dokka versions from [`gradle/libs.versions.toml`](../../gradle/libs.versions.toml).
- The SDK release version is still defined once in the root `build.gradle.kts` (`extra["versionName"]`) and is read by `sdk.android.library` and `sdk.publish`.
- The root build provides the aggregate tasks `testSdk` and `connectedAndroidTestSdk`.
- The Gradle wrapper is updated to 9.5.0.

Documentation updated accordingly: [`AGENTS.md`](../../AGENTS.md), [`CONTRIBUTING.md`](../../CONTRIBUTING.md), [`README.md`](../../README.md), [`TOC.md`](../../TOC.md), the SDK module READMEs ([`sdk`](../../sdk/README.md), [`core`](../../sdk/core/README.md), [`authentication`](../../sdk/authentication/README.md), [`mfa`](../../sdk/mfa/README.md), [`fido2`](../../sdk/fido2/README.md), [`adaptive`](../../sdk/adaptive/README.md)) and the example READMEs. Version references to `3.2.12` in the dependency snippets were bumped to `3.2.13`, and the "target SDK 36" statements for the library modules were replaced by the actual `compileSdk` 37 (targetSdk 36 applies to the demo apps only).

## Security: OW2 ASM 9.11.1

Dependency scanning reported OW2 ASM versions before 9.11 (`asm-9.9.1.jar` in the demo app builds) against the following CVEs. All are denial-of-service issues (excessive memory, CPU or stack use) triggered by crafted class files:

| CVE | Affected component |
|---|---|
| CVE-2026-110257 | `ClassReader.readBootstrapMethodsAttribute()` |
| CVE-2026-110258 | `Label.addSubroutineRetSuccessors()` |
| CVE-2026-110260 | OW2 ASM before 9.11 |
| CVE-2026-110261 | `ClassWriter.COMPUTE_FRAMES` / `MethodWriter.computeAllFrames()` |
| CVE-2026-110262 | `asm-commons` `AdviceAdapter` |
| CVE-2026-110263 | `SignatureReader.parseType()` |
| CVE-2026-110270 | `asm-commons` before 9.11 |
| CVE-2026-110591 | `Analyzer.analyze()` |

**Impact assessment:** The SDK is not exposed. ASM is not a dependency of any SDK module and is not packaged in the published AAR/JAR artifacts or the demo apps. It is only a transitive dependency of build and test tooling (Android Gradle Plugin, Robolectric, JaCoCo), where it processes the project's own compiled classes.

**Fix:** The whole ASM family (`asm`, `asm-commons`, `asm-tree`, `asm-analysis`, `asm-util`) must move together and is now pinned to `9.11.1` in:

| Location | Scope |
|---|---|
| [`build.gradle.kts`](../../build.gradle.kts) `buildscript { dependencies { constraints { … } } }` | Gradle buildscript classpath (AGP) |
| [`build.gradle.kts`](../../build.gradle.kts) `allprojects { resolutionStrategy { force(…) } }` | Test and runtime classpaths (Robolectric, JaCoCo) |
| [`build-logic/build.gradle.kts`](../../build-logic/build.gradle.kts) `constraints { … }` | `build-logic` classpath |

Gradle dependency resolution confirms every ASM module resolves to `9.11.1` (for example `asm:9.9 → 9.11.1` from AGP and `asm-commons:8.0.1 → 9.11.1` from Robolectric). No SDK API or behaviour changes.

## Upgrade Notes

No code changes are required when upgrading from 3.2.12 to 3.2.13.

Developers building the SDK from source must use JDK 17 and the included Gradle wrapper (9.5.0). References to the removed `common-*.gradle` scripts in forks or custom tooling must be replaced by the convention plugins listed under [Build System Changes](#build-system-changes).
