# IBM Verify SDK for Android - Release 3.2.11

## Overview

Version 3.2.11 is a patch release combining one build dependency update, one documentation correction, and a demo app version bump. No SDK production logic was changed.

1. **Netty update to 4.2.17.Final** — `io.netty:netty-codec-http2`, `netty-codec-compression`, and `netty-handler-proxy` force-pinned from `4.2.15.Final` to `4.2.17.Final`.
2. **Browser compatibility documentation** — `AuthenticationActivity` KDoc and `sdk/authentication/README.md` clarify which browsers are verified to support the Custom Tabs redirect contract (Chrome, Firefox, Edge) and explain the `ActivityNotFoundException` symptom when a non-compliant browser is the device default.
3. **Demo app version bump** — example apps bumped from `1.3.4` (versionCode 10) to `1.3.5` (versionCode 11).

## Breaking Changes

None. This is a backward-compatible release. All existing code targeting 3.2.10 continues to compile and run without modification.

## Documentation

### Browser compatibility for the Authorization Code Flow

**Updated:** [`AuthenticationActivity`](../../sdk/authentication/src/main/java/com/ibm/security/verifysdk/authentication/AuthenticationActivity.kt), [`sdk/authentication/README.md`](../../sdk/authentication/README.md)

The `AuthenticationActivity` KDoc and Authentication SDK README have been updated to:

- Correct terminology from "Chrome Custom Tabs (CCT)" to the generic "Custom Tabs" (the protocol is not Chrome-specific)
- Explicitly list the browsers verified to support the full Custom Tabs flow including the redirect contract
- Document the `ActivityNotFoundException: No Activity found to handle Intent` symptom that occurs when a non-compliant browser is the device default
- Clarify that `CustomTabsIntent.Builder.setEphemeralBrowsingEnabled` is a Chrome-specific API that other Custom Tabs providers may ignore

**Verified browsers (redirect works correctly):**

| Browser | Notes |
|---|---|
| Google Chrome | Full support including `setEphemeralBrowsingEnabled` |
| Mozilla Firefox | Full Custom Tabs support; `setEphemeralBrowsingEnabled` may be ignored |
| Microsoft Edge | Full Custom Tabs support; `setEphemeralBrowsingEnabled` may be ignored |

**Root cause of `ActivityNotFoundException`:** The Custom Tabs protocol requires the browser to fire the redirect URI back to the app as a standard `VIEW` intent that `AuthenticationActivity` can receive. Not all browsers that support opening Custom Tabs implement this part of the contract. When a non-compliant browser is the device default, the redirect intent is fired inside the browser process with no registered handler.

**Resolution:** Instruct users to set a supported browser as their device default. The SDK selects the default browser when launching the Custom Tab; there is no API to override this choice without building a custom browser picker.
